## Overview

This document defines **what gets tracked** and **what gets ignored** in this repository. Gitignore patterns follow best practices for modern Node.js/React/Vite projects, with special attention to security, media management, and squad runtime state.

---

## Pattern Categories & Rationale

### 1. **Node & Package Managers**

```
node_modules/
package-lock.json
yarn.lock
pnpm-lock.yaml
bun.lock*
```

**Why ignore:**
- `node_modules/` is generated by `npm install`; should never be tracked (violates single source of truth)
- Lock files (`package-lock.json`, etc.) are local to each developer's environment and OS
- Regenerated automatically on `npm install` — including it bloats the repo

**When to commit:** Never. Lock files are generated; dependencies are defined in `package.json`

---

### 2. **Environment & Secrets** ⚠️ **CRITICAL SECURITY**

```
.env
.env.local
.env.*.local
.secret
.secrets/
secrets.json
private/
credentials/
```

**Why ignore:**
- `.env` files contain API keys, database credentials, OAuth tokens
- `.secret` folder holds sensitive material (e.g., test credentials — already being ignored)
- **NEVER commit secrets.** Period.

**What to use instead:**
- Use environment variables passed via CI/CD (GitHub Actions, deployment platforms)
- Store secrets in GitHub Secrets for CI/CD workflows
- Use `.env.example` (tracked!) to document *required* variables without values
- For local development: create `.env.local` (ignored) from `.env.example`

**Security note:** `.secret/` already tracked? Document in `.gitignore` anyway to prevent accidental commits.

---

### 3. **Logs**

```
logs/
*.log
npm-debug.log*
yarn-debug.log*
pnpm-debug.log*
lerna-debug.log*
*.log[0-9]*
```

**Why ignore:**
- Log files are runtime output; not code
- Can contain sensitive data (API responses, user data)
- Specific to local environment; not useful for other developers

---

### 4. **Build & Bundle Artifacts**

```
dist/
dist-ssr/
build/
out/
coverage/
.next/
*.tsbuildinfo
```

**Why ignore:**
- Generated during `npm run build` or development
- Not source code; regenerated on demand
- Including them increases clone time and repo size

**How developers rebuild:**
- `npm run build` — generates dist/ from source
- `npm run dev` — rebuilds automatically
- TypeScript compile caches (`.tsbuildinfo`) are safe to ignore

---

### 5. **IDE & Editor Files**

```
.vscode/*
!.vscode/extensions.json
!.vscode/settings.json
!.vscode/launch.json
.idea/
*.swp, *.swo, *~
```

**Why ignore:**
- Editor configs are personal preference; VS Code root workspace settings shouldn't be tracked
- Vim/Emacs temporary files (*.swp) are development clutter
- JetBrains `.idea/` varies per developer

**Exception:** `!.vscode/extensions.json` and `!.vscode/settings.json` are tracked to share recommended extensions and consistent formatting.

---

### 6. **OS Files**

```
.DS_Store
Thumbs.db
desktop.ini
.directory
```

**Why ignore:**
- Generated by macOS (.DS_Store), Windows (Thumbs.db), Linux (.directory)
- Not relevant to the project; specific to file manager
- Including them causes cross-OS merge conflicts

---

### 7. **Vite-Specific**

```
.vite/
.vite-cache/
vite.config.ts.timestamp-*
```

**Why ignore:**
- Vite cache directories improve dev server startup
- Timestamp files are generated during builds
- Not necessary for repository; regenerated automatically

---

### 8. **Testing Artifacts**

```
test-results/
playwright-report/
coverage/
.nyc_output/
junit.xml
*-screenshots/
firefox-debug-screenshots/
test-debug-screenshot.png
```

**Why ignore:**
- Test reports are local verification; not source code
- Playwright screenshots are debugging aids (`.headed` mode, test failures)
- Coverage reports are CI/CD output; not tracked
- `test-results/` includes per-run data specific to local environment

---

### 9. **Temporary & Debug Files**

```
*.local
debug/
debug-*.png
migration-reports/
.temp/
tmp/
```

**Why ignore:**
- `.local` extension marks development-only files
- Debug screenshots and reports are one-off troubleshooting
- Migration reports are generated; not source code

---

### 10. **Media Folder — Special Handling** 🎬

```
media/cache/
media/videos/output/
media/videos/*.mp4
media/videos/*.webm
media/audio/*.mp3
media/audio/*.wav
media/audio/cache/
media/assets/temp/
media/assets/cache/
```

**Why ignore specific outputs:**
- Video outputs (`.mp4`, `.webm`) are generated by Remotion during render
- TTS audio cache is regenerated as needed
- Intermediate files bloat the repo

**What IS tracked:**
- `media/templates/` — Remotion composition templates (source)
- `media/scripts/` — build/render scripts (source)
- `media/docs/` — documentation (source)
- `media/public/` — static assets (source)

**Why separate?** Media folder contains both source (templates, scripts) and runtime outputs (videos, cache). Tracking templates ensures reproducibility; ignoring outputs keeps the repo lean.

---

### 11. **Squad & Project-Specific**

```
.squad/orchestration-log/
.squad/log/
.squad/decisions/inbox/
.squad/sessions/
.squad-workstream
.squad/agents/*/cache/
.squad/agents/*/temp/
```

**Why ignore:**
- `.squad/log/` and `.squad/orchestration-log/` are runtime diagnostics; regenerated each session
- `.squad/sessions/` holds session history; local to developer machine
- `.squad/decisions/inbox/` is workflow state; pushed to shared decisions/ on merge
- `.squad-workstream` is a local activation flag for this machine

**What IS tracked:**
- `.squad/team.md` — team roster and roles
- `.squad/decisions/` — approved decisions (committed)
- `.squad/agents/*/charter.md` — agent charters (source)
- `.squad/skills/` — reusable patterns (source)

## Common Issues & Fixes

### Issue: I accidentally committed `.env`

```bash
# Remove from git history (do NOT delete the file)
git rm --cached .env
git commit -m "Remove .env from tracking"
```

Then:
1. Add `.env` to `.gitignore` (already done)
2. **Rotate all credentials in `.env`** — assume they're compromised
3. Force-push to development branch, not main

### Issue: Screenshots are huge and tracked

Screenshots (`.png`, `.jpg`) in project root are now ignored via:
```
*.png
*.jpg
```

They'll still appear in `test-results/` and `*-screenshots/` (also ignored).

### Issue: I want to commit a specific ignored file

Use `git add -f <file>`:
```bash
git add -f .vscode/settings.json  # Force-add even if ignored
```

Then consider adding an exception to `.gitignore`:
```
.vscode/*
!.vscode/settings.json
```

## Maintenance

### Review .gitignore annually:

1. Run `git status --ignored` to spot ignored files
2. Check if new directories (e.g., new build output) should be ignored
3. Update comments if project structure changes
4. Run `git check-ignore -v <file>` to debug "why is this ignored?"

### Add to CI/CD pipeline:

```yaml
# GitHub Actions example
- name: Validate .gitignore
  run: |
    git add .
    if [ -n "$(git status --porcelain)" ]; then
      echo "⚠️ Untracked files found (not ignored). Check .gitignore."
      git status
      exit 1
    fi
```

## Appendix: Excluded Patterns (Not Tracked)

Files that are **NOT** in `.gitignore` (intentionally tracked):
- `package.json` — defines dependencies (always tracked)
- `tsconfig.json` — TypeScript configuration (shared)
- `vite.config.ts` — build configuration (shared)
- `.eslintrc.*` — linting rules (shared)
- `tailwind.config.ts` — styling config (shared)
- `media/templates/` — Remotion source (tracked)
- `media/scripts/` — render scripts (tracked)
- `media/public/` — static assets (tracked)
- `.squad/team.md` — team roles (tracked)
- `.squad/decisions/` — approved decisions (tracked)

These files are essential for reproducibility and team coordination.
